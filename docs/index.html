Personal Publishing Framework

让源材料持续存在，让出版成为可重建的过程。

PPF 是一个以源材料为中心、可迁移、可检查的个人出版框架。它把创作者控制的内容，与格式、构建工具、发布平台和具体版本分开。

PPF 解决什么问题

很多作品一旦进入某种编辑器、文件格式或平台，就很难再被完整地迁移、复现和长期维护。PPF 把“源材料是什么”“如何构建”“发布了什么”“当前版本是什么”明确分开，使出版不再是一次性的导出动作，而成为能够被理解、检查和再次构建的过程。

源材料归创作者控制

源材料是主要对象，应当保持可携带、可备份、可迁移，而不是被某个平台锁定。

格式与平台可以替换

HTML、EPUB、PDF、DOCX、LaTeX 等是输出形式，不应取代创作者真正拥有的源材料。

构建过程可以检查

输入、工具、版本、转换步骤和输出结果可以被记录，从而支持复现和排错。

发布版本可以识别

发布、版本、修订和归档状态被明确命名，读者和合作者不必猜测看到的是什么。

出版生命周期

Source
源材料创作者持续控制的正文、数据、资产、元数据和项目结构。
Build
构建把源材料转换为一种或多种可交付格式，并保留可检查的过程信息。
Publish
发布让某个输出通过网站、文件、仓库或其他渠道被访问。
Release
版本明确冻结一次有意发布的版本，记录其范围、时间和对应的源状态。
Archive
归档保存足以理解和重建该版本的材料、工具信息与关联记录。

安全默认

新配置的原创或未发布作品默认使用 private canonical source。Continuous Web 可以同步准备，但在得到人类明确公开发布授权前保持 restricted + authenticated。访问凭据只保留在服务端访问层；仓库只记录 policy reference。以后把 Web 改为 public，不要求源仓库也公开。

适合什么工作

PPF 可用于个人书籍、论文、研究笔记、课程材料、教学资源、知识库、项目文档和其他需要长期维护或多格式发布的创作工作。它不要求使用 AI；它首先是一套帮助个人保留控制权、提高可迁移性和重建能力的出版结构。

与 AHICP 组合

如果项目还需要人主导的 AI 协助、来源保留、决定记录和责任边界，可以把 PPF 与 AHICP 组合使用。两者也可以通过 Composite Starter 一起开始。

Personal Publishing Framework

Let the source endure, and make publication rebuildable.

PPF is a source-centered, portable, inspectable framework for personal publishing. It separates creator-controlled material from formats, build tools, delivery platforms, and identifiable releases.

What PPF is for

Once work is placed inside a particular editor, file format, or platform, it can become difficult to migrate, reproduce, and maintain. PPF separates the source, the build process, the published output, and the release state. Publication therefore becomes a process that can be understood, inspected, and rebuilt rather than a one-time export.

Source remains creator-controlled

The source is the primary object. It should remain portable, backed up, and migratable instead of being locked to a platform.

Formats and platforms can change

HTML, EPUB, PDF, DOCX, and LaTeX are outputs. They should not replace the material the creator actually owns.

Builds are inspectable

Inputs, tools, versions, transformation steps, and outputs can be recorded for reproduction and troubleshooting.

Releases are identifiable

Publication, version, revision, and archive states are named explicitly, so readers and collaborators know what they are seeing.

The publication lifecycle

SourceThe text, data, assets, metadata, and project structure that the creator continues to control.
BuildTransform the source into one or more deliverable formats while retaining inspectable process information.
PublishMake an output accessible through a website, file, repository, or another delivery channel.
ReleaseIdentify an intentional release, including its scope, date, and corresponding source state.
ArchivePreserve enough material, tool information, and related records to understand and rebuild the release.

Safe default

Newly configured original or unpublished work defaults to a private canonical source. Continuous Web may be prepared at the same time, but remains restricted and authenticated until explicit human public-release authorization. Reader credentials stay in the server-side access layer; repositories store only a policy reference. Making the Web public later does not require making the source repository public.

What it supports

PPF supports personal books, papers, research notes, course materials, teaching resources, knowledge bases, project documentation, and other work that needs long-term maintenance or multiple publication formats. It does not require AI; it is first a structure for retaining personal control, portability, and rebuildability.

Compose with AHICP

When a project also needs human-led AI assistance, source preservation, recorded decisions, and clear responsibility boundaries, PPF can be composed with AHICP. The two can also be started together through the Composite Starter.
